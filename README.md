# dsh-workspace-activity

DSH Web GUI 的工作区活跃度显示插件（规划完成，代码未开始）。

目标：在侧边栏工作区这一块按活跃程度显示工作区与会话，帮助判断「此刻哪些工作区在动、最近谁在用」。

- 讨论稿 v0.1.2：[docs/discussion/工作区活跃度显示讨论稿-v0.1.2.md](docs/discussion/工作区活跃度显示讨论稿-v0.1.2.md)
- 实施稿 v0.1：[docs/implementation/工作区活跃度插件-实施稿-2026-10-23.md](docs/implementation/工作区活跃度插件-实施稿-2026-10-23.md)
- 当前状态：实施稿已出，待开工（S0 起）。

## 已经拍板的部分

| 问题 | 结论 |
| --- | --- |
| 第 4 个图标位置 | 先不定，先按 A（侧边栏全局面板入口）做功能 |
| 参考对象 | Codex 桌面应用的 Activity / Priority 视图（已从本机 app.asar 核实） |
| 首版形态 | 两种视图模式：「按工作区」（默认）/「按时间分节」，不做综合评分 |
| 活跃度口径 | 四项都要算；首版只接现成的两项（最近活动、运行状态），活动量与文件改动放 v1.1 |
| 时间窗 | 可配置，默认 24 小时 |
| 接口面 | 2 个端点（`ws-activity/ping`、`ws-activity/snapshot`）+ 2 个插槽（`sidebar.panellist`、`main`） |
| 只读 | 不写会话、不写工作区、不发模型请求 |

## 从浏览器插件接过来的教训

实施稿 §二 列了 14 条（内部 API 不稳定、bundle 扫描、一次性 profile 探针、CLI 版本混用、手改 patch、裸路由、DOM 依赖、iframe 认证、bundle 崩溃、热更不一致、大文件、验收造假、端到端盲区、轮询长挂），每条都有规避动作；其中「内部 API 无稳定承诺」只能缓解（锁版本 + 降级 + 升级回归清单）。
